# ADR: Add Loops Page Under 連続処理

## Status

Accepted

## Context

ComfyUI core now ships `Start Loop` / `End Loop` (category `utilities/looping`), which repeat the part of a workflow enclosed by the pair. Unlike Queue, List, and Batch, a loop can feed the result of one iteration back into the next through `initial_iteration_value` / `current_iteration_value` / `next_iteration_value`.

The page was first drafted under `データ操作`, after `条件分岐`, on the grounds that loops and conditionals are the two control structures. That placement does not work:

- `データ操作` is ordered before `連続処理` in the nav, so a reader reaching the page has not yet read `List`.
- The page depends on List throughout: the `List` mode and `list_item`, and `Create List` / `Get Item From List` for carrying several values in one `next_iteration_value`.
- The article's pivot ("これだけならループを使う必要はあまりありません。List 処理や Queue の繰り返しでも似たことはできます") only lands if the reader already knows Queue and List.

`連続処理` is the group that answers "how do I handle more than one thing", and Queue / List / Batch are its three existing answers. Loops belong there as the fourth, the one that can carry state forward.

## Decision

Add a new page:

- Section: `data-utilities`
- Slug: `loop`
- Title: `ループ処理`
- Navigation group: `連続処理`
- Position: after `バッチ・動画` and before `リアルタイム処理`

This keeps loops adjacent to the Queue / List / Batch trio it builds on and contrasts itself against, rather than separating them with `リアルタイム処理`.

The slug is singular. It was `loops` in the first draft, which does not fit this section: singular marks a page about one mechanism (`queue`, `list`, `batch-video`, `realtime`), plural a page enumerating many items (`data-types`, `color-adjustments`, `text-ops`, `wildcards`). Loops are one mechanism. Separately, the asset prefix is singular because it modifies the rest of the name and English uses the singular there — `loop_simple`, not `loops_simple`.

The EN display title and nav label are plural, "Loops". A standalone topic name is not attributive, and upstream names the feature "Generic Loops"; `Queue` and `List` stay singular only because each names one thing. Identifiers (slug, navId, asset prefix) stay singular either way.

Media originals and workflow JSON live under `data-utilities/loop/` and are prefixed `loop_`: the folder says where a file belongs, the prefix says what it shows, so each name stands alone as `/ops/style-writing.md` requires.

JA is the source. The owner asked for localization in the same pass, so EN and ZH pages, nav entries and news rows ship together with it.

The article does not use the name "Generic Loop": that is the upstream feature name and appears nowhere in the ComfyUI UI, where the nodes are simply `Start Loop` and `End Loop`.

Nesting (`parent_iteration`) is deliberately out of scope. Covering every input of the nodes would turn the page into a node reference rather than an article.

## Consequences

- `ops/ia.md` must list `ループ処理` under `データ / 画像ユーティリティ` > `連続処理`, after `バッチ・動画`.
- `src/_data/nav.{ja,en,zh}.yml` include `loop` in the `連続処理` group, with the labels `ループ処理` / `Loops` / `循环处理`.
- `src/content/{ja,en,zh}/news.md` each gain one row for the new page.
- The page is new and unpublished, so no redirect is needed for the earlier `データ操作` placement.
- The carried-value example relies on a heterogeneous `Create List` surviving a loop, which was broken before ComfyUI v0.36.0 (Comfy-Org/ComfyUI#16343, fixed by #16345). Screenshots and workflows must be produced on v0.36.0 or later.
