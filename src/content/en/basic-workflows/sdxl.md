## What is SDXL?

SDXL (strictly speaking, SDXL 1.0) is the official successor from Stability AI, the developer of Stable Diffusion 1.5. (There was also a Stable Diffusion 2.1 line, but well... its performance...)

Compared with Stable Diffusion, there are roughly two big differences:

**A two-stage `base` and `refiner` setup**

- Basic text2image is done with the `base` model alone.
- It's designed so that the `refiner` model then runs image2image as a "finishing" pass that polishes details and texture.

**A change in training resolution**

- Stable Diffusion 1.5
  - Trained mainly on 512 x 512px square images
- SDXL
  - Trained mainly on 1024 x 1024px with various aspect ratios
  - It's easier to generate at higher resolutions from the start, and it copes reasonably well with portrait and landscape compositions.

## text2image with Just the base Model

First, let's keep it simple and do text2image with `base` alone.

You can do basic generation just by swapping the Checkpoint for SDXL base in the [SD1.5 text2image workflow](/en/basic-workflows/sd15-text2image/).

![](/media/basic-workflows/sdxl/legacy_gyazo_c812a47ff8d57de7f90be3b85d1a5f58.png){media=image}

[](/workflows/basic-workflows/sdxl/sdxl_text2image_base.json)

* Aim for a resolution of roughly 1M pixels (around 1024 x 1024px).

  * Examples: 1024 x 1024 / 896 x 1152 / 1152 x 896, etc.

### CLIPTextEncodeSDXL

For its text encoder, SDXL base combines two kinds of CLIP (OpenCLIP-ViT/G, CLIP-ViT/L).

ComfyUI also has a node that lets you feed separate text to each CLIP, but I'll say it up front: **you don't need to use it.**

![](/media/basic-workflows/sdxl/legacy_gyazo_55a896ac7ae4544942d9242853a4d9c9.png){media=image}

[](/workflows/basic-workflows/sdxl/sdxl_text2image_base_cliptextencodesdxl.json)

* If you put the same prompt into both CLIPs, it behaves almost the same as the `CLIP Text Encode` node.
* Experiments have also shown that putting the same text into both CLIPs tends to give the most stable output.

## base + refiner

Next, let's finish the image generated by `base` with `refiner`.

### Generate with base → image2image with refiner

SDXL base and SDXL refiner use the same latent representation.
So the latent generated by base can go straight into the refiner-side KSampler for image2image.

![](/media/basic-workflows/sdxl/legacy_gyazo_4bc82a63f933e5538c45ca11832c5f08.png){media=image}

[](/workflows/basic-workflows/sdxl/sdxl_text2image_base_refiner.json)

* 1. 🟪 text2image as usual with SDXL base (outputs a latent)
* 2. 🟨 Connect that latent to a KSampler that uses SDXL refiner
* 3. 🟨 image2image at a low `denoise` (e.g., 0.2 to 0.3)

  * The refiner specializes in adding detail, so a very small amount is plenty.

The idea is to keep base's original look and let refiner polish only the fine details and texture.

### Switching mid-sampling (KSampler Advanced)

A slightly smarter approach is to switch from base to refiner partway through sampling.
This uses the [KSampler (Advanced) node](/en/basic-workflows/ksampler-advanced/).

![](/media/basic-workflows/sdxl/legacy_gyazo_9f6609b33de0a955ca5d9a86ba882ab4.png){media=image}

[](/workflows/basic-workflows/sdxl/sdxl_text2image_base_refiner_advanced.json)

* 🟪 Sample with SDXL base up to the middle
* 🟨 Switch to SDXL refiner for the remaining steps
* 🟦 Set when to switch with the `int` node.

Personally, I prefer image2image because it's easier to follow, but it may be worth remembering that you can switch between base and refiner within a single sampling pass like this.

## You Don't Need the refiner, but "refiner-like Thinking" Matters

### Refiner-less SDXL Models

There are many derivative models based on SDXL (community and commercial), and most of them are **tuned to give good enough image quality without a refiner**.

To put it a bit bluntly, the "post-process with the refiner" design was partly a compromise to make up for how limited base was on its own back then.

### Refiner-like Thinking

Still, the idea itself of "finishing one image across multiple models" holds up well even today.

* Models whose style you like, but which don't follow prompts very well
* Or the reverse: models that follow prompts well, but whose style isn't to your taste

There are tons of these "almost, but not quite" models.

In situations like this, SDXL's refiner-like thinking comes in handy.

* First, generate a base image with a model that's good at composition and following the prompt
* Then finish that image with image2image using a model whose style you like

With a two-stage setup like this, you can build a best-of-both-worlds workflow: "composition from model A, style from model B".

SDXL's base / refiner is just one concrete example of this.
Try finding your own ways of "combining multiple models".
